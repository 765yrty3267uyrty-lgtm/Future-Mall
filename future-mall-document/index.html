FUTURE MALL

1. The Complete Picture

This document outlines the complete submission requirements for the Future Mall capstone project. The project integrates seven distinct modules into a single cohesive portfolio piece demonstrating full-stack development, branding, cybersecurity education, and data management skills.

Each module functions independently while sharing a unified design system — colors, typography, spacing, and visual language — defined in the shared/ constants. This ensures visual consistency across all deliverables.

The final submission must include all modules, properly organized in a single ZIP archive, with a live GitHub Pages deployment for the web-based components.

  • Seven integrated modules: three Python console applications, one desktop GUI, two web applications, and one brand identity package.
  • Unified design system via shared/constants.py, shared/constants.css, and shared/constants.js.
  • GitHub Pages deployment for website and digital awareness modules with automated CI/CD.
  • Professional documentation including master README, architecture docs, and brand guidelines.
  • All code clean, typed, tested, and portfolio-ready.
What You Submit for Each Task
  • Complete source code for the module in its designated folder.
  • README.md with installation, usage, and run instructions.
  • Requirements/dependencies file (requirements.txt, package.json, etc.).
  • Test files demonstrating core functionality.
  • Screenshots or GIFs showing the working application.
  • Any assets (images, icons, fonts) required by the module.

The Form of the Files

All files must follow a consistent naming convention and organizational structure. This ensures the evaluation team can navigate the submission easily and run automated validation scripts.

Use lowercase with hyphens for file and folder names (kebab-case). Avoid spaces, uppercase letters, or special characters. Python files use snake_case. The root ZIP folder must be named exactly:

future-mall-capstone.zip

Additional Instructions

Do not include virtual environments, node_modules, __pycache__, .git, or build artifacts in the ZIP. These will be generated during evaluation. Include a .gitignore in the root.

All paths in code must be relative. No absolute paths referencing your local machine. Use environment variables or config files for any machine-specific settings.

Warning: Submissions with absolute paths, missing dependencies, or non-standard naming will receive automatic deductions. Run the provided validation script before submitting.
The Three Rules
1
Correct file naming & submission: All files use kebab-case (folders/files) or snake_case (Python). Root ZIP named exactly future-mall-capstone.zip. No extra nesting.
2
Every drawing should be clear and readable: Diagrams, screenshots, and assets must be high resolution (minimum 1920px wide for images), legible at 100% zoom, and use the brand color palette.
3
Sharing & formatting: Live URLs must be accessible without authentication. GitHub Pages links in README. No password-protected repos. Code formatted with Prettier (JS/CSS) and Black (Python).
These three rules are validated automatically. Failure on any rule blocks further evaluation.

6. Timing

The capstone project is due on the date specified in the course schedule. Late submissions incur a penalty of 10% per day up to a maximum of 5 days. After 5 days, the submission will not be accepted.

The submission window opens 48 hours before the deadline. Early submissions are encouraged and will not be penalized. You may update your submission any number of times before the deadline — only the last submission is evaluated.

Extensions are granted only for documented emergencies (medical, family, technical infrastructure failure). Requests must be submitted to the course instructor at least 24 hours before the deadline with supporting documentation.

The evaluation period begins immediately after the deadline. Results and feedback will be available within 10 business days. You will receive a detailed rubric breakdown and qualitative comments.
